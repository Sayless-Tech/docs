Reports are collections of dashboard tiles. Use a report to organize related charts and data views for a workflow, team, account segment, or operating review.

## Overview

Use reports when several related dashboard views should live together. Post-sales teams commonly create reports for support operations, onboarding health, renewal reviews, account activity, conversation volume, and follow-up tracking.

Each report opens as a grid. Dashboard tiles inside the report can be arranged, resized, opened, duplicated, or removed depending on your permissions.

Go to [Reports](https://joinsayless.com/reports), or use `G` then `R`.

> Reports are available on Startup and higher. The Free plan has a report limit of `0`; Startup includes up to `3` reports, Business includes up to `10`, and Enterprise is unlimited in the current client policy.

| Report surface | Route pattern | Use it for |
| --- | --- | --- |
| Report list | `/reports` | Create, search, sort, filter, open, duplicate, share, or delete reports. |
| Report detail | `/reports/{reportPath}` | Arrange and review the dashboard tiles in one report. |
| Dashboard detail | `/reports/dashboard/{dashboardPath}` | Open and configure one dashboard tile. |

## Work with reports

The reports area supports creating, opening, editing, duplicating, clearing, sharing, and deleting reports depending on permissions.

### Create a report

Create a report when your team needs a new place to organize related dashboard tiles.

The reports page exposes a new report action, search, sort, filter, multi-select deletion, row menus, and command menu actions.

### Open a report

Open a report to review the dashboard tiles inside it.

Report detail pages use a grid layout. Users with update access can move and resize dashboard tiles. Layout and description changes are saved from the report header.

### Edit a report

Edit a report when the name, icon, description, layout, or sharing settings need to change.

The report name can be edited from the report header. The report description can be shown in the body and saved with layout changes. The report menu also exposes edit actions where available.

### Duplicate a report

Duplicate a report when you want a copy of the report and its dashboards.

Duplicating a report creates a new report and copies its dashboard tiles, so the new report can be adjusted without changing the original.

### Clear a report

Clear a report when you want to remove all dashboard tiles but keep the report itself.

Clearing a report deletes the dashboards associated with the report and resets the report layout.

### Delete a report

Delete a report only when it should no longer be available.

Deleting a report also removes its associated dashboards and membership records.

## Report details

Report details show the dashboard tiles inside the report.

### Dashboard grid

The report body is a grid of dashboards. Each tile previews one dashboard’s configured chart or data view.

Users with update access can drag tiles, resize them horizontally, and save the new layout. Opening a tile takes you to the dashboard detail page.

### Dashboard tiles

Each dashboard tile has its own data source, filters, visualization, aggregation, interval, sorting, and description. Those settings are configured on the dashboard detail page, not directly on the report container.

Available dashboard chart types include line, bar, stacked bar, pie, table, single value, summary, and circle-style visualizations where configured.

| Chart type | Best for |
| --- | --- |
| Line | Trends over time. |
| Bar or stacked bar | Comparisons across groups. |
| Pie | Part-to-whole breakdowns. |
| Table | Exact rows and values. |
| Single value or summary | One important number. |

### Report description

Use the report description to explain the review or operating question the report is meant to support.

The description is limited in the app and is best kept short: for example, “Weekly onboarding health review” or “Renewal risk indicators for enterprise accounts.”

### Sharing

Use reports and dashboards to give teammates a consistent view of the same data.

Reports support general access and member-specific access. General access determines whether the report is visible broadly in the workspace; member access gives named teammates a specific permission level.

| Permission | What it allows |
| --- | --- |
| Read | View the report. |
| Read & Write | View and edit report configuration. |
| Admin | View, edit, share, and delete the report. |

Workspace admins can read reports in the workspace. For private reports, non-admin teammates need explicit membership. A report creator can share their report, and teammates with Read & Write or Admin access can share when the report’s access rules allow it.

> If the Share button is missing, you may not have permission to share the report. Ask the report owner or a workspace admin to update access.

## Report controls

Report controls help manage the report container and the dashboard tiles inside it.

### Create dashboard

Use **New dashboard** from a report detail page to add a new dashboard tile to the report.

Dashboard creation is only available when you have permission to create dashboards in that report and the workspace plan has dashboard capacity.

### Save and revert layout changes

When you move or resize dashboard tiles, the report shows save and revert actions. Save updates the report layout. Revert restores the last saved layout and description.

### Open raw data

Dashboard actions can take you back to the underlying source data when the dashboard has a configured data source. Supported destinations include tickets, broadcasts, conversations, and metric events.
